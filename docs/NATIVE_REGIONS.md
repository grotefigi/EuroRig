# Offline country packages

A `.eurorig` ZIP has exactly three top-level entries:

| File | Purpose |
| --- | --- |
| `routing.tar` | Uncompressed TAR of Valhalla graph tiles |
| `display.sqlite` | Disk-backed roads and FTS4 search (format 2) |
| `manifest.json` | Version, source, date, attribution and SHA-256 |

Legacy format 1 uses `display.europack` instead. No maps are bundled in the app.
Required manifest: `format: 2`, `engine: "valhalla"`, `native_version: "0.6.3"`
and both payload hashes. ZIP compression saves download bytes; import streams
the files to disk so routing can memory-map the TAR. Device paths/configuration
are generated by the app; the engine's network tile URL is removed.

places and no missing geometry. ZIP: 415,239,820 bytes; installed data about 871 MB.
`pyvalhalla==3.6.3` matches the Android core revision
`e2f017b16080f49203de245a211b09efab09cf72`. `osmium==4.3.1` streams display/search.
Builds include admin enrichment but no timezone polygons yet. Time-dependent
restrictions and country truck laws are not road-validated.

```text
python tools/build_country.py work/romania --pbf romania.osm.pbf
python tools/make_catalog.py catalog.json romania=work/romania/Romania.eurorig
```

Install `tools/map-requirements.txt` in a dedicated Python 3.12 environment. Use
a fresh directory. Other countries need appropriate `--name`, `--start`, `--end`.
Provenance records source dates/hashes, versions and counts. Binary reproducibility
across hosts is unverified. Original Romania PBF accompanies the public release.

## Display schema

SQLite `user_version=1`. `metadata` stores JSON name, bounds, seeds, source dates,
counts and attribution. `roads` stores OSM IDs, names, levels, bounds and polyline6
geometry. `cells` indexes 0.02-degree grid coverage; long roads use bounds/level
indexes. `places` and Unicode FTS4 `search` normalize accents for prefix matching.
Viewport queries load at most 2,000 roads/40,000 road vertices. Display/search
never supply routing decisions.

## Download and install

Catalogue format 1 has `native_version`, `coverage`, `europe_complete` and `maps`
entries with `id`, `name`, `url`, `bytes`, `sha256`, `osm_timestamp`. Relative URLs
work on static HTTPS hosts and GitHub Releases. All-Europe requires
`europe_complete: true`; the current catalogue is Romania-only. Russia entries
are excluded. Completeness must be audited before enabling the full-Europe flag.
Resume validates byte ranges. Truncation preserves partial bytes; checksum
failure discards the corrupt download. HTTPS establishes publisher trust.

Imports stream to internal UUID directories. Fixed names, duplicates, sizes,
free space, hashes, TAR/tile paths and expected SQLite schema are checked.
Selection changes after native initialization. Failed imports preserve the
active map. Stale staging directories are cleaned on load. These checks do not
certify every native tile record or restriction. Downloaded archives remain for
country selection; one extract is active at a time in 0.3.

Cross-border routing requires a coherent graph build. Independently built country
graphs cannot be concatenated; European partitioning must preserve shared tile
identities, hierarchy and borders.

Validation ceilings: 128 GiB TAR, 16 GiB SQLite, 128 MiB legacy graph, 64 KiB
manifest, 200 MiB storage reserve. These are not measured continental capacity.
32-bit devices reject TARs over 1.5 GB. Updates need space for both versions.

Country data is ODbL 1.0 with attribution, original source and build provenance.
