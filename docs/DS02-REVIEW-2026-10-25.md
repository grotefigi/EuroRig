## Claim dispositions

| Claim | Review decision and source evidence |
| --- | --- |
| C01: tunnel B cannot be saved | Rejected. The active `InterfacePages` profile editor explicitly maps options to `{0,2,3,4,5}`. The legacy dialog also converts nonzero spinner position to `position + 1`. B becomes 2; stored code 1 is deliberately invalid. |
| C02: derived `hazmat` loses load distinctions | Not a demonstrated bug. `Truck` retains `hazardousLoad` and `tunnelCode` separately. The broad boolean is conservative native costing; `RestrictionRule.hazardViolation` checks water, explosives and tunnel category separately. Full ADR consignment semantics remain unsupported. |
| C03: native request omits dimensions and axles | Rejected. `NativeRouter.request` includes height, width, length, loaded weight, axle load/count, top speed and all three global avoidance switches. The detailed ADR fields are handled by the added audit; permitted mass is explicitly informational. New tablet payload checks verify the actual JSON independently. |
| C04: permitted mass is informational | Confirmed documented limitation. `Truck.permittedWeight`, `exceedsPermittedMass` and the UI warning preserve the distinction. Routing uses actual loaded mass. This is not evidence of complete regulation by plated mass. |
| C05: repeated 40 t defaults are contradictory | No failing case demonstrated. `Truck.standard` and legacy persistence defaults intentionally agree. Migration of absent permitted mass to the previous loaded mass needs an explicit future product decision; neither number proves a legal maximum. |
| C06: lack of a normalized axle-count column means no enforcement | Rejected as an enforcement claim. Raw `maxaxles` survives in tags; `RestrictionRule.exceeds` and `AccessPolicy.fatal` compare it with `truck.axles`. Invalid text is refused. Broader import coverage still requires fixtures. |
| C07: nonnumeric stored speed silently uses a default | Rejected. `Store.measurement` calls `Double.parseDouble` when the key exists. The default applies to a missing value; invalid values enter the enclosing profile recovery path. Do not infer silent per-field fallback. |
| C08: axle key drift | Rejected as reported. `Store.saveTruck` and `VehicleProfiles` both use `axle`. Other keys intentionally differ between separate preferences and named-profile JSON serializers. A serializer round-trip test would be useful, but different schema names alone are not corruption. |
| C09: unequal model maxima prove a defect | Not demonstrated. Bounds are implementation constraints, not country law. The genuine 200 t model / 100 t native bridge difference remains explicit and tested, without claiming 200 t routing support. |
| C10: coverage audit misreads unit strings | Not reproduced. The audit reads numeric database columns and raw tags separately. Column/tag consistency is a useful future audit requirement; the submitted claim supplies no failing compiled record. |

The report also claims no avoidance tests or fixture fields. `RoutingTest.tollAvoidanceIsAnExclusion`, `CountryPreferencesTest` and the native benchmark's truck avoidance fields contradict this. Heuristic fixture-to-test mapping is not a test-coverage oracle.

Follow-up to C07 found a different, real defect: the enclosing recovery path silently replaced the entire malformed profile with `Truck.standard()`. This checkpoint keeps the editor available but marks the profile for review, clears accepted routes and blocks planning/guidance until a valid profile is saved. It also stops an active session if malformed profile data are loaded. Companion-preference corruption tests exercise numeric parsing, wrong stored types, nonfinite values and recovery without editing the driver's saved truck.
