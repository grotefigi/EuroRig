# Truck and ADR capability matrix

Source-reviewed 2026-10-25. This describes implementation and measured software behavior, not legal vehicle approval. Roadmap B1 remains in progress. Model representation, native request acceptance, mapped-rule enforcement and complete country coverage are different claims.

## Fields and enforcement

| Input | Representation and native request | Added enforcement and evidence | Remaining acceptance |
| --- | --- | --- | --- |
| Loaded height, width, total length | Positive finite metres; model ceilings 10 m, 10 m, 50 m. Sent as `height`, `width`, `length`. | Numeric mapped limits in `RestrictionRule.exceeds` / `AccessPolicy.fatal`; tablet payload equality and native clearance/refusal fixtures pass. | Equality/boundary corpus across imported rules, endpoint changes, alternatives and reroutes; no claim that model ceilings match native engine ranges. |
| Actual loaded gross mass | Positive finite tonnes; model ceiling 200 t. Native bridge explicitly refuses above 100 t without clamping. | Sent as `weight`, independently of permitted mass. Six JVM tests and tablet JSON boundary checks pass. Native fixtures exercise 40 t and over-limit 60 t refusal. | No real 100 t journey is certified. Above 100 t is unsupported by this bridge. Country and vehicle-category legality is not inferred from a numeric profile. |
| Documented permitted maximum mass | Positive finite tonnes, at most 200 t; stored separately. Not sent as a native costing field. | `exceedsPermittedMass` reports loaded mass above permitted mass with 0.001 t comparison tolerance; visible profile warning. Exact and next-floating-point boundary tests pass. | Plated-mass-specific regulations and full legality checks are absent. The tolerance is a UI warning contract, not permission to overload. |
| Maximum loaded axle mass | Positive finite tonnes, at most 40 t and not above gross mass; sent as `axle_load`. | Mapped `maxaxleload` numeric limit and native refusal fixture. Exact payload check passes. | Axle-group/bogie load distribution, axle spacing and national combination rules are unrepresented. |

| Toll, ferry and unpaved avoidance | Three booleans sent as native exclusions; country preferences are separately keyed and audited. | Both opposite JSON combinations checked in every mode and delivery state; existing JVM toll and country-preference tests pass. | Missing country metadata is refused. Real-country feature completeness and multi-stop alternatives remain open. |
| Delivery/private access | Destination-bound trip authorization, not a truck capability or global waiver. | Added access audit, permission lifetime and hard limits remain active. Native fixture refuses low clearance and `hgv=no` even with delivery selected. | Complete expiry/revocation/reroute/profile-change corpus belongs to B4. |
| Malformed saved profile | Editor remains available with a visible review warning; replacement display defaults cannot authorize a route. | Planning and guidance guards reject it; loading invalid values stops active guidance. Saving a valid reviewed profile clears the review state. Isolated companion-preference tests cover malformed numbers/types, NaN, valid decimal values and legacy floats. | Missing historical fields still use legacy defaults; no claim of complete profile migration or vehicle legality is made. |

## Standard combinations and unsupported structure

| Requested configuration | Current status |
| --- | --- |
| Rigid truck | Aggregate dimensions, masses and axles can be represented and checked against mapped scalar limits. No dedicated rigid-type legal rule model is established. |
| Tractor with semitrailer | Aggregate inputs work identically. Tractor/semitrailer identity, component dimensions, axle groups and articulation are not engine inputs. This is not complete configuration support. |
| Drawbar truck with trailer | Aggregate inputs can be entered; drawbar-specific regulations and component geometry are not represented. |
| Multiple trailers / national standard combinations | Named-profile JSON has a `trailers` presentation value, but `VehicleProfiles.truck` does not transfer it into `Truck`; no trailer-count enforcement may be claimed. Trailer-dependent uncertain restrictions require review/refusal, not a guessed permission. |
| All standard ADR profiles | Partial mapped load/tunnel support only. The current broad flag and three-bit load mask cannot express all ADR classes, quantities, exemptions or mixed consignments. |
| Permit-dependent abnormal loads | Later user-agreed scope. Model acceptance of an unusually large number neither checks a permit nor approves routing. |

## Decisions and next work

Keep exact loaded and permitted masses separate. Keep the existing explicit native refusal above 100 t; never silently clamp to obtain a route. Do not raise the native cap or reduce safety enforcement based on a worker summary. A profile can be representable while routing is unsupported; make that distinction clear before future support acceptance.

Next B1 work is a combination/consignment schema decision tied to actual route-audit needs, independent boundary fixtures and a clear unsupported-profile UI contract. B5 supplies licensed current rule evidence through the shared source pipeline. Neither a green suite nor a dense restriction overlay closes missing country/municipal data.
